# 大肥鱼 · 活动感知实验台 V1 设计

- 日期：2026-11-09
- 状态：V1 已进入实现与验证；实现范围、测试命令与剩余限制见 [模块说明](../src/perception/README.md)。真实桌面权限行为和运行中 GUI 不因合成测试通过而视为已验证。
- 模块边界：大肥鱼插件内的独立业务模块，随插件安装和初始化，复用宿主运行能力、资源路径、路由和 GUI；核心不依赖其他业务模块。仅原生采集器为额外进程，不新增 Node 服务或端口。
- 技术方案：[活动感知独立模块 V1](activity-perception-technical-v1.md)。
- 目标平台：macOS 第一版；保留 Windows 采集适配边界，不实现 Windows。
- 本阶段目标：采集电脑活动信号，分析近期活动，通过可视化观察实际结果，并自动清理过期数据。

## 1. 定位与范围

活动感知用于观察电脑上的活动线索，推测主人当前的活动状态。最终可作为大肥鱼行动决策的输入，但 V1 仅做实验台，不接入行动决策。

典型场景：主人持续使用 IDE、终端或独立 Codex 应用，模块根据近期前台应用分布、交互情况和持续性，产生“开发倾向”等摘要。不能因为软件在后台运行，就认定主人正在忙。

### 纳入

1. 每 5 秒采集一次 macOS 活动快照。
2. 本地规则分析及可解释的活动摘要。
3. 当前状态、近期时间轴、历史摘要的只读展示。
4. 原始采样及历史摘要分别设置保留期限，自动清理。
5. 基本开始、暂停、停止控制和异常状态显示。

### 不纳入

- 规则编辑界面、人工标注、判断反馈、评分。
- 历史规则对比、历史重算、实验评审工作流。
- 截图、录屏、OCR、窗口标题、网页 URL、键盘内容、剪贴板、文档内容。
- 全量进程扫描、命令行读取、终端内容理解。
- 大模型分析、云端上传、主动提醒、自动行动、行动决策接线。
- 工作效率评价、情绪推断、长期用户画像。
- Windows 实现、开机自启、复杂权限管理界面。

## 2. 数据流与模块边界

```text
macOS 采集适配器（每 5 秒）
    ↓
原始采样存储（短期）
    ↓
分析器（每 30 秒，观察最近 5 / 15 分钟）
    ├── 当前状态（每次分析更新）
    └── 历史摘要（每分钟及重要状态变化时保存）
              ↓
        本地可视化界面

清理器：每 5 分钟清理过期原始采样及摘要，启动时补清理
```

模块职责：

| 模块 | 职责 |
|---|---|
| 系统适配器 | 获取平台信号，返回统一采样结构，不做活动推断 |
| 存储层 | 保存采样、摘要和最新状态，提供有界查询 |
| 分析器 | 计算窗口指标，推断状态并保留理由 |
| 清理器 | 根据期限执行删除，报告清理结果与错误 |
| 界面 | 展示采集事实、分析结论、数据质量及保留情况 |

插件安装包包含感知模块及支持平台的采集资源。插件启动时初始化模块和清理任务，实际采集默认仍需用户显式开始；初始化不等于自动监测。采集不依赖页面保持打开。暂停、停止由明确控制完成；插件 dispose/卸载或宿主退出时结束采集器、定时器和数据库连接。卸载后不继续后台采集或清理，下次初始化补清理。

## 3. 采集设计

### 3.1 固定周期

- 每 5 秒生成一条快照，不叠加另一套高频采样。
- 通过包含休眠经过时间的单调时钟发现采样缺口；可用系统通知仅作边界增强，不是 V1 必需机制，不承诺完整锁屏检测。
- 每日持续运行约产生 17,280 条原始采样。
- 固定采样无法捕获两次采样之间所有短暂切换，界面和指标均不宣称完整记录。

### 3.2 采样字段

| 字段 | 含义 |
|---|---|
| `sampleId` | 唯一采样标识 |
| `runId` | 本次采集运行标识，区分重启和恢复边界 |
| `observedAt` | UTC 观察时间；界面按本地时区显示 |
| `monotonicMs` | 本次运行中的单调时间，用于时长计算 |
| `foregroundApp` | 应用名称、Bundle ID；不可获取时为空 |
| `idleSeconds` | 距最近系统输入的时间；不可获取时为空 |
| `sessionState` | `unlocked / locked / unknown` |
| `quality` | 正常、字段缺失及错误原因，不用猜测值补齐 |

不记录按键、点击位置或鼠标轨迹。闲置时间只表示无键鼠输入，不等于没有工作或人已离开。

### 3.3 数据连续性

- 休眠、暂停、退出、采集失败形成数据缺口，不补造采样。
- 相邻有效采样在正常间隔内可近似形成活动区间；超过允许间隔（初始为 10 秒）不将整个间隔归给上一应用。
- 遇到明确休眠、锁屏或暂停边界，立即截断相应活动区间。
- 跨运行或跨已知中断不累计“连续前台时长”。
- 时长依赖单调时间，不直接相减墙上时间；系统时钟跳变时记录质量问题并重新建立时间边界。
- 应用前台时长均为采样估算值，不是精确工作时长。

## 4. 分析设计

### 4.1 周期与窗口

- 每 30 秒计算一次。
- 使用最近 5 分钟和 15 分钟两个窗口。
- 冷启动时明确展示实际覆盖时长及数据不足，不把少量样本放大成完整窗口。
- 分析使用本地确定性规则，不调用模型。
- 参数保存在模块配置中，不提供规则编辑或重算界面。

### 4.2 基础指标

- 各应用及类别的估算前台时长、占比。
- 当前应用连续前台时长。
- 观察到的应用切换次数（不是完整切换次数）。
- 当前无输入时长。
- 近期有输入的采样占比：初始以 `idleSeconds <= 60` 为近期输入，指标不代表工作效率。
- 有效数据覆盖率、缺失字段和中断区间。

应用占比以窗口内全部有效前台观察时长（包含未分类应用）为分母，并同时提供覆盖率。锁定及缺失区间单独展示，不算作应用使用。未分类应用计入“未分类”，不得静默剔除而抬高其他类别占比。

### 4.3 应用分类

- IDE：开发。
- 独立开发工具：经明确应用身份映射后归为开发。
- Terminal、iTerm 等：终端，作为辅助线索，不默认等于开发。
- 浏览器：浏览器，不进一步声称阅读、娱乐或开发。
- 沟通软件：沟通。
- 无映射应用：未分类。

Codex 若在终端或浏览器中运行，基础采集只能识别终端或浏览器；不承诺识别其中的具体工具或任务。

应用分类采用内置映射及配置文件，不增加编辑界面。

### 4.4 分析输出

| 字段 | 取值或含义 |
|---|---|
| `activity` | 开发倾向、浏览器活动、沟通、混合、未知 |
| `interaction` | 近期有输入、持续无输入、锁定、未知 |
| `continuity` | 持续、短暂、数据不足 |
| `confidence` | 低、中、高；启发式等级，不是校准后的概率 |
| `stateSince` | 当前推断状态开始时间，不等同于开始工作的时间 |
| `evidence` | 有界的结构化指标和简短理由，不复制原始采样列表 |
| `windowStats` | 5 / 15 分钟指标及覆盖率 |
| `analyzedAt` | 分析时间 |
| `sourceThrough` | 本次分析所使用的最新观察时间 |
| `freshness` | 新鲜、过期、不可用 |
| `ruleVersion` | 内部规则版本，用于解释数据来源，不提供版本对比功能 |

初始开发倾向规则：15 分钟窗口有效覆盖率至少 80%，开发类占比至少 60%，开发类累计至少 5 分钟。终端只作为解释和辅助证据，不能独立触发高置信开发判断。数据不足时输出未知或低置信，不凭空补足窗口。

浏览器、沟通等类别采用明确的主导占比规则；没有主导类别且覆盖足够时为混合，缺乏证据时为未知。精确规则与防抖参数在实现时固定为可测试配置，不扩展成用户调参产品。

活动切换应经过连续两次分析确认，避免短暂切换造成跳变；锁屏、停止和数据失效不等待该防抖。无输入不会直接终止开发活动判断，而是单独降低当前参与程度的确定性。

### 4.5 新鲜度

- 距最后有效采样超过 20 秒，采集状态标记过期或中断。
- 距最后成功分析超过 90 秒，分析状态标记过期。
- 新采样停止但分析仍在运行时，不得仅刷新 `analyzedAt` 就使旧结论重新变新鲜；同时检查 `sourceThrough`。
- 暂停或停止后，最后结果可保留展示，但必须标记非实时，不供未来决策当作当前事实。

## 5. 数据存储与过期清理

### 5.1 两层持久化数据

| 数据 | 保存频率 | 默认保留期 | 用途 |
|---|---|---|---|
| 原始采样 | 每 5 秒 | 1 小时 | 滚动分析及近期事实时间轴 |
| 历史摘要 | 每分钟及重要状态变化 | 7 天 | 历史状态变化展示 |
| 当前状态（仅内存） | 每次分析覆盖更新 | 最新一份，不跨模块重启恢复 | 实时展示及未来消费接口 |

持久化仅有原始采样和历史摘要两张表；当前状态在内存保存，模块重新初始化后为空，不把历史结果恢复成当前事实。最新状态仍必须遵守新鲜度；超过摘要保留期清空内容，不能永久保留陈旧事实。

原始采样正常约保留 720 条；按 5 分钟清理周期，可能暂存约 780 条。每分钟历史摘要 7 天约 10,080 条，另有状态变化摘要。具体磁盘大小取决于字段、索引和数据库实现，不能按记录数直接承诺字节数。

历史状态变化仅比较活动、交互、连续性等核心字段；计时增长或理由数值变化不单独触发额外保存。定时保存与状态变化同一轮发生时合并成一条，历史摘要写入最多每个分析周期一条。

### 5.2 清理配置

```text
sampleIntervalSeconds = 5
analysisIntervalSeconds = 30
analysisWindowMinutes = [5, 15]
rawRetentionMinutes = 60
summaryRetentionDays = 7
cleanupIntervalMinutes = 5
```

保留期可在模块配置中调整，不增加复杂设置界面。校验原始保留期大于最长分析窗口并预留至少一个分析周期，否则拒绝无效配置。

### 5.3 删除语义

1. 程序启动时先补做过期清理，然后进入正常运行。
2. 运行中每 5 分钟清理一次；暂停采集不暂停清理。
3. 原始采样与摘要分别按期限删除，实际删除允许有一个清理周期的延迟。
4. 不在“被分析过一次”后立刻删除采样：同一采样仍可能被后续滚动窗口使用。
5. 原始数据清理不依赖分析成功，分析持续失败也不能无限保留原始数据；显示异常和无法恢复的数据缺口。
6. 清理幂等、分批执行，避免阻塞采集和查询。每次分析读取一致的窗口快照，避免与删除竞争。
7. 清理失败时记录错误、停止新增采样和摘要，下个周期重试；不得静默宣称已删除。清理恢复后需用户手动开始采集。
8. 写入失败时停止采集并显式报错，不用无限内存缓存伪装成功；V1 不构建多级容量治理机制，通过 TTL、失败即停止新增和有界查询控制数据量。
9. 程序关闭期间不会执行清理，重新启动后补清理；不承诺关闭期间按时从磁盘移除。

### 5.4 SQLite 空间管理

推荐 SQLite。原始采样和摘要分别建立时间索引，存储位于用户运行数据目录，不放入源码仓库。

- 删除记录后允许空闲页被后续写入复用；数据库文件不必每次物理缩小。
- 管理 WAL checkpoint，避免日志文件长期增长。
- 不每 5 分钟执行全库 VACUUM。
- 普通运行日志只保存计数、状态和错误，不重复输出原始活动记录。
- 过期清理是逻辑数据删除，不宣称安全擦除磁盘或清除系统备份。

原始数据到期后，历史界面只能读取摘要，不支持重新分析或还原原始时间轴。摘要自身到期后相应历史也不可查询。

## 6. 可视化设计

一个轻量实验台，除运行控制外只读，不做实验会话管理、标注或反馈工作流。

### 6.1 运行状态

- 采集中、已暂停、已停止、异常。
- 最近采集和分析时间、运行时长。
- 开始、暂停、停止按钮。
- 采样缺失、权限缺失和分析过期的明确提示。

暂停和停止均中断连续性；重新开始建立新边界，不把中间时间计入活动。停止不删除已有数据，仍按保留期限清理。

### 6.2 当前采集与分析

左侧显示前台应用、应用标识、距最近输入时间、会话状态、字段可用性。

右侧显示活动类型、交互状态、连续性、置信等级、推断持续时间、窗口分布及判断依据。不展示未经定义的“忙碌分数”或“有效工作时长”。

### 6.3 时间轴

三条对齐时间轴：

1. 前台应用观察。
2. 交互、锁屏及数据缺口。
3. 分析状态。

默认查看近期数据；原始时间轴只覆盖尚未清理的最近一小时。更长范围只显示摘要，不把摘要展开成伪造的原始采样。可点击查看某条摘要的统计与理由，不提供重算操作。

使用浏览器查看实验台会改变前台应用，这一影响如实反映在采集结果中。由于不读取 URL，不承诺识别“当前浏览器正在显示实验台”，也不自动排除这段活动。

### 6.4 数据保留状态

展示原始采样条数、摘要条数、保留期限、最近清理时间、删除条数及清理异常。计数使用存储查询结果，不使用理论采样数冒充实际数量。

## 7. macOS 技术方向与接入约束

- Swift 薄常驻采集器，通过 `NSWorkspace` 获取前台应用身份；每 5 秒输出一行 JSON，宿主直接启停进程，不设计双向 IPC、握手或自动重启系统。
- 使用系统闲置时间接口获取距最近输入的时间，不安装键盘内容监听。
- 休眠通过单调时间缺口和可用系统边界信号识别；锁屏接口需验证，不可靠时返回未知，不承诺完整检测。
- 基础目标是不依赖屏幕录制权限；具体接口和二进制分发需原型验证，不先承诺所有环境免授权。
- 分析、存储、清理和查询运行在插件现有宿主进程中，不新开 Node 服务，不预设 worker。SQLite 驱动需根据宿主实际能力验证，不强制另装 Node 24。
- 数据目录由现有资源管理模块提供；实验台接入大肥鱼现有 GUI 和路由，复用宿主访问保护，不新增端口或认证系统。
- 插件安装包携带原生二进制；构建发生在开发/发布阶段，不要求用户单独编译或安装 Swift 开发环境。
- 核心分析与其他业务解耦，通过薄宿主接线接入生命周期；后续大肥鱼消费摘要，不直接访问数据库。
- Windows 后续替换采集器与应用身份映射，复用分析、清理和展示；V1 未支持平台显示 unavailable/unsupported，不影响插件其他功能。

## 8. 隐私边界

用户显式开始后采集，运行状态可见。仅保存应用级元数据和摘要，本版全部在本地处理，不上传模型服务。原始记录仅保留分析所需的短期范围，摘要也有过期时间。

不把“原始数据无用”理解为“采集后可永久保存”：对大肥鱼有价值的是经过计算且仍然新鲜的摘要，而不是应用切换流水。

## 9. 实施顺序与验收

### 第一阶段：采集与事实展示

- 能每 5 秒观察前台应用和闲置时间。
- 界面能核对当前采集值与近期时间轴。
- 锁屏、休眠、暂停、重启不产生虚假连续使用时长。
- 字段不可用、短暂切换可能漏采等限制明确可见。

### 第二阶段：分析与摘要展示

- 每 30 秒更新分析，展示覆盖率、结论和理由。
- IDE、终端、浏览器交替使用时能形成可解释的活动结果。
- IDE 留在前台但长时间无输入时，不断言主人仍在主动工作。
- 浏览器或终端内的 Codex 不被宣称为已识别的具体工具。
- 无数据、陈旧数据和采集中断不被展示为可靠当前状态。

### 第三阶段：清理与运行验证

- 用自动化测试验证 TTL 边界、启动补清理、暂停期间清理、分析失败仍清理。
- 验证清理与分析并发时结果一致，不读取半个窗口。
- 验证清理失败和磁盘写入失败会显式报错并停止新增数据。
- 验证插件初始化、dispose 和热重载不留下采集器、重复定时器或数据库句柄；模块错误不拖垮其他插件功能。
- 连续运行超过原始保留期限和至少两个清理周期，确认原始采样数量处于预期范围。
- 使用缩短 TTL 的测试配置验证摘要到期删除，无须实际等待 7 天。
- 原始数据清理后摘要仍可展示，界面不提供已不存在的原始详情。
- 检查 WAL 与数据库空间复用，不将文件未立即缩小误判为未清理。

本阶段完成标准是采集可观察、分析可解释、存储有期限、异常不伪装正常；不以“准确知道主人在做什么”或“已接入大肥鱼决策”作为完成声明。

## 10. 后续边界

未来大肥鱼默认只读取当前摘要，必要时读取有界的近期摘要，不默认获取原始采样。后续决策接入、Windows 支持或更丰富的信号采集另行设计，不混入 V1。
