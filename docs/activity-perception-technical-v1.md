# 活动感知模块 V1 · 插件托管技术方案

日期：2026-11-09。状态：V1 实现与验证中。当前桌面宿主同一 Electron 可执行文件已验证 node:sqlite 可用，原生 arm64/x64 构建与合成信号测试已进行；真实桌面权限行为、物理 Intel 机器和运行中 GUI 仍需单独验收。实现说明见 [模块 README](../src/perception/README.md)。

产品范围见 [活动感知实验台设计](activity-perception-design-v1.md)。本方案替代此前的独立服务方案：**感知模块随大肥鱼插件安装和启动，复用插件宿主的运行能力，仅原生采集器是额外常驻进程。**

## 1. 最终边界

- 这是大肥鱼插件内的独立业务模块，不是需要单独安装和启动的产品。
- 插件安装包包含感知代码、页面资源和目标平台所需的采集器；不要求用户另行部署 Node 服务。
- 插件启动时初始化模块、存储、查询入口及清理任务；插件 dispose/卸载时释放资源并结束采集器。
- 模块初始化不等于自动监测。V1 延续显式开始采集：初始 stopped，用户开始后才启动原生采集器。不做开机自启或重启后自动恢复采集。
- 不新开 Node 进程，不新增监听端口，不另建独立实验网站。
- 感知核心不依赖 ABS、social、persona 等业务模块；不接入行动决策，不调用模型。
- macOS 第一版，Windows 后续替换原生采集适配器，复用分析、清理、接口和界面。

这里的“独立”指职责、代码和接口边界独立，不要求脱离插件单独运行。

## 2. 运行结构

```text
DSH 现有宿主进程
  └── 大肥鱼插件
       ├── 感知宿主接线
       │    ├── 初始化 / dispose
       │    ├── 现有资源管理：数据与二进制路径
       │    └── 现有路由和 GUI 入口
       └── 感知模块
            ├── 原生采集器管理
            ├── 每 30 秒分析
            ├── SQLite 存储
            └── 每 5 分钟清理
                    ↑ stdout JSON Lines
              原生常驻采集器
                ├── macOS：Swift
                └── Windows：后续实现
```

新增运行成本是一个薄原生采集进程和插件内的少量计算，不是新增一套服务。页面通过现有 GUI 展示，使用既有宿主认证与路由约定，不另建登录或 token 系统。

## 3. 代码组织和接入点

建议新增以下目录；均为规划，尚未创建：

```text
src/perception/
  core.js             区间统计、分类、防抖、新鲜度
  collector.js        启停采集器、解析和校验采样
  store.js            两张表、查询、TTL
  service.js          模块状态与定时任务
  host.js             插件生命周期、资源与路由接线
  client/             感知实验台
  native/macos/       Swift 源码与构建配置
  tests/              核心、存储、生命周期测试
```

实际文件扩展名、前端构建接线按现有项目约定确定，不另建与根项目割裂的应用工程。

- core 是纯逻辑，可注入时钟，用固定采样测试，不启动 DSH 或采集器。
- collector 只接收宿主已解析的采集器绝对路径和配置，不自行猜安装目录。
- store 只接收数据库路径和数据库适配器，不直接依赖宿主上下文。
- service 组合上述部分，暴露 start/pause/stop/getCurrent/query/dispose。
- host 负责与插件框架连接，不把宿主对象传入分析算法。
- 复用现有 resources 提供的插件数据根目录，建议 perception 子目录；数据不放源码目录。
- OS/架构判断及二进制定位遵循现有 platform/resources 边界，业务代码不散落 process.platform 判断。

必须修改插件安装包包含范围、构建接线、启停接线和界面入口；不再保留“不得修改插件入口”的旧限制，但不修改其他业务模块行为。

## 4. 运行时和打包

### 数据库

继续采用 SQLite 作为目标存储，但不强制独立 Node 24，也不假定 DSH 提供 node:sqlite。

实现前确认：

1. 当前宿主 Node 版本、执行模式及可用 SQLite 能力。
2. 项目或宿主是否已有可复用数据库接口，以及其生命周期和并发约束。
3. 若需新增 SQLite 依赖，确认目标系统、架构、宿主 ABI 与插件打包兼容性。

优先复用可靠现成能力；驱动选择必须在原型中验证。不得为满足某个驱动而偷偷增加 Node 服务，也不把完整活动数据退回无界 JSON 日志。

### 原生程序

- macOS 使用 Swift 编译的常驻命令行程序，运行时不要求用户自己安装 Swift 开发环境。
- 发布包携带目标架构二进制，或安装包按平台提供对应资源；源码编译发生在开发/发布阶段，不默认安装时现场编译。
- V1 发布支持范围按实际验证的 macOS 版本和架构声明，不能把仅本机编译成功视为全平台可用。
- Windows 未实现时返回 unsupported，插件其他模块继续正常运行。
- 需验证安装后的执行权限、签名/隔离属性、路径含空格及更新替换二进制的行为。

## 5. 薄常驻采集器

### 生命周期与数据流

Node 宿主通过绝对路径 spawn，禁止 shell 拼接。启动即采集，结束进程即停止，不设计双向业务命令。

1. 启动立即采样，此后每 5 秒一次，不重入、不补发错过的周期。
2. stdout 一行一个 JSON，及时 flush；stderr 仅短诊断，不输出活动流水。
3. SIGTERM 正常退出；父进程持有的 stdin 管道 EOF 或 stdout broken pipe 时退出。
4. stdin 只用于检测父进程生命周期，不传 start/stop/ACK。
5. 每次启动生成新 runId，旧子进程退出前不允许启动另一个。

不做 hello 握手、独立心跳、多级自动重启或消息总线。收到首条合法采样代表采集可用；是否持续收到采样用于检测超时。

### 信号

必备：前台应用身份与名称、距最近系统输入的时间。

macOS 候选接口：NSWorkspace.shared.frontmostApplication、CGEventSource.secondsSinceLastEventType。接口权限、异常值与目标系统行为必须原型验证。

锁屏是可降级字段，不可靠时为 unknown，不把闲置等同于锁屏或离开。使用包含休眠经过时间的单调时钟检测长间隔；若通过轻量系统通知发现边界，在下一条采样标 continuityBreak，不新增事件表或消息类型。

不采标题、URL、内容、键盘内容、剪贴板、完整进程列表和命令行，不申请屏幕录制来实现基础采集。

### 固定格式

```json
{
  "schemaVersion": 1,
  "seq": 17,
  "observedAtMs": 1794226800000,
  "monotonicMs": 85000,
  "foregroundApp": {
    "platform": "macos",
    "id": "com.microsoft.VSCode",
    "name": "Visual Studio Code"
  },
  "idleSeconds": 12,
  "sessionState": "unknown",
  "continuityBreak": false,
  "missing": ["lockState"]
}
```

宿主补 runId、receivedAtMs。应用身份携带平台，不假设 Windows 有 Bundle ID；分类映射由 platform + id 决定。未知应用不按名称包含 code 等词猜类别。

单行最大 16 KiB；累计无换行缓冲超限即报错并停止。校验版本、枚举、数值与字符串长度；字段缺失返回 null/unknown，不造默认事实。

## 6. 插件生命周期

- 插件初始化：模块配置校验、数据库打开、过期清理、注册查询与页面、启动清理定时器。采集保持 stopped。
- 感知模块初始化失败：显示不可用及原因，不让大肥鱼其他模块整体失败。
- 开始：spawn；第一条合法采样持久化后进入 running。20 秒无首条采样则终止采集器并报错。
- 正常运行超过 20 秒无采样：标为过期；若子进程仍存活，后续恢复时可继续，但必须截断连续性。
- 意外退出或格式错误：进入 error，用户手动开始，不自动重启。
- 暂停/停止：立即将结果置为非实时，SIGTERM；3 秒未退出再 SIGKILL，收到退出后允许重启。
- 插件 dispose/卸载：先阻止新任务，停止采集器和定时器，注销该模块入口，关闭数据库；结束逻辑幂等。
- 插件热重载/重新加载必须先释放旧实例，避免两个采集器和重复定时器。
- 宿主异常退出：依赖 EOF/broken pipe 结束采集器，必须本机实测无遗留进程。

暂停或停止采集不停止清理；插件已经卸载或宿主退出时无法继续清理，下次初始化补清理。卸载不默认销毁历史数据，数据删除遵循插件既有数据管理策略，不擅自新增卸载擦除行为。

## 7. 插件内分析与存储

不引入 worker 或任务队列框架。每次分析约数百条样本，使用短小、同步的存储操作与纯函数分析；清理分批让出事件循环。实际测试若发现阻塞宿主，再据此优化。

两张表：

| 表 | 核心字段 |
|---|---|
| samples | id、run_id、seq、observed_at_ms、received_at_ms、monotonic_ms、app_platform、app_id、app_name、idle_seconds、session_state、continuity_break、quality_json |
| summaries | id、analyzed_at_ms、source_through_ms、rule_version、payload_json |

- samples 对 (run_id,seq) 去重；分别为采样接收时间和摘要时间建索引。
- 不设 boundaries/current_state/service_meta 表；SQLite user_version 保存 schema 版本。
- 当前采样、当前分析和最近清理结果在内存；重新初始化后当前结果为空，不能把历史摘要恢复成实时事实。
- 写入成功后才发布对应内存结果；失败显式报错，不用缓存伪装成功。
- 摘要上限 32 KiB，只保留有界统计与理由，不复制原始采样。
- SQLite 使用短事务；若使用 WAL，配置 checkpoint，不能让读取事务跨请求持有。

## 8. 分析规则与新鲜度

每 30 秒分析最近 5/15 分钟。没有新采样不重复制造新摘要，错过定时只执行当前轮。

相邻采样 run 不同、continuityBreak、单调时间不递增或间隔 >10 秒，之间记缺口。否则近似把 [A,B) 归给 A，裁剪到窗口；最后采样最多延展 5 秒。时长按单调时间计算，墙上时间跳变时截断连续性并提示。

- coverage = 有效前台时长 / 完整窗口时长，冷启动不缩小分母。
- categoryShare 的分母包含未分类应用，排除缺失和已知锁定区间。
- 15 分钟覆盖率 <80%：未知、数据不足；5 分钟展示短期统计。
- 开发占比 ≥60% 且累计 ≥5 分钟：开发倾向。
- 否则浏览器/沟通占比 ≥60%：对应活动；两种已知类别各 ≥20%：混合；其他未知。
- 终端仅辅助解释，不独立推断开发；浏览器不进一步猜阅读或娱乐。
- idle ≤60 秒为近期输入，超过为无近期输入，null 为未知；已知 locked 优先。无输入不等于离开。
- 活动变化连续两轮确认；确认后持续 ≥5 分钟为持续，否则短暂。暂停、停止和失效立即撤销实时性。
- confidence 是证据强度等级，不是概率；覆盖 ≥90%、主导占比 ≥80%且近期输入可标高，满足普通判断为中，证据不足为低。

输出 activity、interaction、continuity、confidence、activitySince、windowStats、evidence、analyzedAt、sourceThrough、ruleVersion。交互变化不重置活动持续时间。

历史每分钟或核心状态变化时保存，同轮合并，最多每 30 秒一条。当前摘要每轮更新。

每次查询动态计算 freshness：采样 >20 秒、分析 >90 秒、非 running 或来源旧 run，均不作为新鲜结果。暂停后可展示最后结果但必须标非实时；超过摘要 TTL 清空内存结果。

## 9. 清理

默认 raw=1 小时、summary=7 天、每 5 分钟清理；初始化补清理。原始保留期必须大于最长窗口并留至少一个分析周期。

- 原始按 receivedAt，摘要按 analyzedAt 清理。单次分析完不立即删样本，因为后续滚动窗口仍会使用。
- 每批最多 500 行，按时间索引取主键再删；批次间让出事件循环。
- 查询同时过滤过期记录，不返回等待物理删除的数据。
- 清理不依赖分析成功。清理失败显示错误并停止新增采样/摘要，下轮重试；恢复后需手动开始。
- 磁盘写失败停止采集，不建立无限内存缓存。
- UTC 回拨可能延迟 TTL，前跳可能提前删除；检测到时间跳变时提示，不引入跨重启逻辑时钟体系。
- 配置启动时加载，缩短期限可删除现存数据，延长不能恢复已删记录。
- WAL 清理后 PASSIVE checkpoint，正常关闭尝试 TRUNCATE；不周期性 VACUUM，允许页复用。
- 普通插件日志只记录有界错误和计数，不复制应用流水，不另建活动日志归档。

原始正常约 720 条，含清理延迟约 780 条；一分钟历史摘要 7 天约 10,080 条，另有状态变化记录。验证实际文件/WAL 大小，不按记录数承诺磁盘字节数。逻辑删除不是安全擦除。

## 10. 宿主接口与界面

沿用现有插件路由前缀，在其下增加 perception 子路由。以下为相对接口语义，准确路径在宿主接线时确认，不另开 HTTP server：

| 接口 | 用途 |
|---|---|
| GET status | 采集状态、当前采样、错误、清理统计 |
| GET current | 当前摘要和 freshness，无数据 data:null |
| GET timeline | 最多 1 小时原始区间，返回实际可用范围 |
| GET summaries | 有界分页，默认 120，最多 500 条，受 TTL 限制 |
| POST start/pause/stop | 幂等生命周期控制 |

权限、来源校验和错误格式遵循宿主及插件现有约定，不弱化现有保护，不新造独立认证系统。未来大肥鱼只消费 current 与有界 summaries，V1 不注册行动工具。

现有大肥鱼 GUI 增加“感知”入口，单页显示运行控制、当前采样、当前分析、三层时间轴和清理情况。每 5 秒刷新当前值、每 15 秒刷新时间轴，隐藏页面停止轮询。离线/插件不可用时明确显示，不继续增长实时状态。

更早历史只展示摘要，无规则编辑、标注、反馈、重算。查看实验台会改变前台浏览器活动，如实展示，不读取 URL 来排除自身。

## 11. 实施与验证

1. 宿主接入审查：确认生命周期、资源路径、平台约束、路由、客户端构建及 SQLite 能力。
2. 薄 Swift 常驻原型：前台/闲置信号、5 秒 flush、权限降级、EOF/信号退出。
3. 插件模块接线：安装包携带资源，初始化/开始/停止/dispose；无独立服务或端口。
4. 两张表与 TTL，然后纯函数分析、只读查询和 GUI。
5. 至少 75 分钟运行试验，摘要 TTL 使用缩短测试配置验证。

重点测试：

- 核心算法可脱离宿主测试，窗口、缺口、冷启动、防抖和未知分母正确。
- 初始化失败不拖垮插件；平台不支持或二进制缺失有明确提示。
- 插件安装后资源可定位；打包二进制可执行；用户无需另启 Node 或安装 Swift 编译器。
- dispose/热重载无残留子进程、重复采样、重复定时器或数据库句柄泄漏。
- TTL、启动补清理、停止期间清理、分析失败仍清理、清理失败停止新增、写失败可见。
- 休眠后不补造采样、不累计缺口；锁屏不可靠则显示未知。
- 采集、分析和清理不会造成可观察的宿主响应退化；测量耗时后再决定是否需要进一步隔离。

方案与实现验收分开记录：代码和合成测试不替代真实桌面与现有 GUI 验收。具体构建、测试结果和尚未完成项目以任务交付记录为准。
