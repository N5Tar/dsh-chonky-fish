## 1. 已确认的产品决策

1. 首次引导是独立的 **hello 模块**，不是把各设置页面简单串起来，也不是新的 Agent 或 ABS 决策器。
2. 基础流程包括人格设置、是否开启感知、ABS 时间流速、ABS 防打扰时间；钉钉为可跳过的附加流程。
3. 人格使用一份预设的完整 Persona Prompt，可查看与编辑；不提供“温柔 / 活泼 / 直接”等性格底色卡，也不把几句话的补充设定冒充完整人格。
4. **不设置“允许主动互动”开关。** ABS 提供状态，大肥鱼自身做决策；首次引导不让用户再次配置这项产品行为。
5. 沿用现有大肥鱼 UI：浅蓝色系、白色圆角卡片、柔和角色场景与原生角色素材，不另造绿色桌宠视觉。
6. 引导应轻量、友好、可返回调整、可恢复。已有用户不得因缺少引导标记而被覆盖配置。

## 2. 现状与设计差距

以下为源码核对结果，不是实机兼容性或线上接通证明。

| 项目 | 当前实现 | 本设计要求 |
|---|---|---|
| 模块布局 | 业务在 `core/modules`，DSH UI/适配在 `app/dsh`，非 UI 公共实现位于 `app/shared` | 按同样边界增加 hello，不新增跨端共享 UI |
| 人格 | 预设人格 + `chonkyfish_supplement` + `chonkyfish_modules`；`state.prompt` 是补充人格 | 增加完整预设人格的读取、版本与覆盖机制，不能直接把全文塞入补充字段 |
| 状态保存 | Host 状态写入含 `generation` 校验，并写临时文件后替换 | Hello 保留未编辑字段，冲突时重新读取，不用旧快照覆盖整个状态 |
| 感知 | 已有状态查询和 `start / pause / stop` 控制 | 显式选择、能力检查、执行后回读，不能用选中态代替采集运行态 |
| ABS | 支持 `time-scale` 与 `rest-hours`，同时仍有 `off / shadow / active` 模式；配置默认 `shadow` | UI 不增加主动互动开关，也不因点击下一步偷偷切换 mode；运行模式与产品目标的对齐须单独核定 |
| 钉钉 | 已有配置、连接状态、主人配对与会话桥接 | 用独立附加向导串联真实阶段，不把保存配置当成连接/配对成功 |
| 首次状态 | 本次核对未发现独立 hello 模块 | 新增版本化引导状态与持久化，明确首次安装与已有资料的区别 |

### 2.1 必须先解决的两个接入点

**完整人格不是现有补充字段。** 当前装配入口见 [人格说明](../core/modules/persona/README.md)、[补充变量实现](../core/modules/persona/supplement.js) 和 [DSH 预设](../app/dsh/packaging/cordis.patch.yml)。现有装配中能力说明动态插入，不能在编辑人格时把实时能力描述复制成静态文本、丢弃模板变量或叠加第二份身份设定。完整人格编辑是拟新增能力，需先确定 Host 装配与存储契约。

**隐藏开关不等于修改运行模式。** [ABS 配置](../core/modules/abs/config.js) 当前默认 `shadow`；[HTTP 适配](../app/dsh/adapters/abs/http.js) 对切换 `active` 仍要求 `confirmActive`。用户确认的是“不在 Hello 设置主动互动开关”，不是已验证仓库默认模式完成调整。Hello 不调用 mode 操作、不绕过现有条件；正式发版前须在 ABS / Host 的独立变更中决定并验证目标运行方式。

## 3. 模块职责与边界

建议按现有架构新增以下位置，均为拟议，不代表已存在：

| 位置 | 职责 |
|---|---|
| `core/modules/hello/` | 引导版本、步骤状态、草稿校验、提交编排及恢复规则 |
| `app/dsh/ui/hello/` | DSH 专属欢迎页、表单、预览和完成页 |
| `app/dsh/adapters/hello/` | 将 Host 当前配置、运行能力和业务服务连接到 hello 用例 |
| `app/shared/storage/hello/` | 引导状态持久化适配，路径由统一资源管理提供 |

依赖方向：Hello 调用人格、感知、ABS、社交已有用例；各业务模块不依赖 Hello。不要通过模块互相调用 HTTP 绕一圈，也不要从 UI 直接写业务配置文件。

Hello 只负责“引导、校验、提交、确认结果”。不负责 Agent Loop、ABS 状态演进、任务调度、模型提供方、全局通知静音、钉钉协议或操作系统采集实现。未来桌面 APP 可以复用核心用例与素材，但拥有自己的 UI，遵循 [架构调整设计](architecture-refactoring-design-v1.md)。

## 4. 用户流程

```text
首次进入 → 欢迎 → 名称与完整人格 → 感知选择 → ABS 相处节奏
                                                ↓
                                      提交并回读基础设置
                                                ↓
                                         完成摘要 / 小鱼塘
                                                ↓ 可选
                         钉钉准备 → 凭据 → 连接 → 配对 → 收发验证
```

步骤间允许返回；切换步骤只保存草稿，不立即启动感知或连接钉钉。退出保留非敏感草稿。下一次打开可以继续，提供“重新开始”时应说明只重置引导草稿、不重置真实设置。

### 4.1 欢迎

- 标题建议：“很高兴，游进你的生活。”
- 展示三件事：认识彼此、划好感知边界、找到相处节奏。
- 主按钮“开始认识你”；说明约两分钟、可随时调整、钉钉可稍后连接。
- 不要求先理解 ABS 原理，不出现高级调试或资料目录配置。

### 4.2 名称与人格

- 名称优先读取已有值；新用户建议“大肥鱼”。名称限制应与服务端契约一致，不照搬原型的演示限制。
- 默认选项目维护的完整人格预设，展示名称、说明、版本；不制作性格分类器。
- “查看 / 编辑完整人格 Prompt”渐进展开。默认无需编辑，长文本支持滚动、保存前检查、恢复预设与修改提示。
- 正式页面必须加载真实预设全文。加载失败显示错误和重试，不允许把占位文字保存为人格。
- 设计上区分“可编辑人格正文”和“系统装配的动态能力说明”。预设标识、版本、覆盖内容应可追踪；升级不能静默覆盖自定义文本。
- 若保留历史补充人格，要明确它与完整人格的关系并给出迁移预览，不自动删除或重复拼接。
- 不能因编辑人格而赋予额外工具权限；不修改已经提交的历史模型请求。

### 4.3 感知选择

- 两个同等清楚的选项：“开启感知”“暂不开启”；首次不预选开启，必须明确选择。
- 说明收益：结合前台应用与空闲时长了解忙碌/离开等状态。
- 说明边界：不读取截图、窗口标题、网址、键盘内容或剪贴板；具体范围以 [感知设计](activity-perception-design-v1.md) 与实际采集器为准。
- 本地采集分析不等于信息永不进入模型；查询得到的状态摘要可能进入模型上下文，不承诺“全部数据绝不离开设备”。
- 读取能力与状态，区分未开启、运行中、暂停、不可用、失败。当前原生构建面向 macOS arm64/x64；其他环境应以实际能力返回为准，不能仅凭平台名伪装可用。
- 选择开启后，基础设置提交阶段再执行启动，并回读状态。若缺少依赖或权限，给出原因、重试与“暂不开启继续”，不阻塞基础聊天。
- 已有采集用户重新进入引导时按实际状态回填；选择暂不开启若会停止既有采集，应明确告知，不当成无副作用的跳过。

### 4.4 ABS 相处节奏

- 展示“内部时间流速”，推荐 `1×`，快捷档位 `0.5× / 1× / 10×` 是引导层建议，不是改变底层范围。
- [时钟实现](../core/modules/abs/clock.js) 当前允许有限数值 `0–120`，`0` 为暂停。已有自定义值应原样显示，不强行吸附到快捷档位。
- 例：“现实 1 小时 = 大肥鱼内部 1 小时”。不表述为回复速度，也不保证主动消息频率。
- 防打扰显示开关与起止时间。[现有休息规则](../core/modules/abs/rest.js) 默认开启，`23:00–08:00`，按固定 UTC+8 现实时间计算，支持跨午夜，起止不得相同。
- 首屏明确时区；不随 ABS 倍率加速，不无声改成浏览器本地时区。
- 限制说明：“安静时间限制 ABS 主动发起，不影响你主动聊天、已有任务及其他计划。”不承诺全应用静音，也不承诺强制中止已经执行中的行为。
- 不出现主动互动开关；不因用户改流速修改 ABS mode。ABS 状态与大肥鱼行动决策是不同职责。

### 4.5 完成与首次体验

- 展示名称/人格版本、感知真实状态、流速与安静时段；各项可回到对应步骤调整。
- 只有持久化与回读确认后才能说“已完成”；部分失败显示逐项结果，保留成功部分并允许重试。
- 主按钮进入小鱼塘。静态示例问候与真实模型回复要区分，不能把本地演示当成已启动 Agent。
- 钉钉入口作为次要卡片：“离开电脑，也可以找到我。”提供“以后再说”，不影响基础引导完成。

## 5. 钉钉附加向导

沿用 [钉钉接入说明](../core/modules/social/DINGTALK.md)，不重新实现社交模块。

1. **准备应用**：企业内部应用、机器人、Stream 模式、发布与可见范围；建议先只对自己开放，不要求公网回调。
2. **填写凭据**：Client ID / AppKey、Robot Code、Client Secret 分开；不假设 Robot Code 等于 Client ID。
3. **连接**：保存与连接状态分开显示。错误给出可操作原因，允许修正、重试或退出。
4. **主人配对**：使用服务返回的一次性配对信息与有效期；在机器人私聊完成，不展示真实身份标识或凭据到日志。
5. **收发验证**：明确告知将发送的测试内容与目标，用户点击后实际测试；显示已发送、已收到或尚未验证，不能仅凭“已连接”判成功。

真实配置可能启用入站自动回复并产生模型用量，应在提交前说明。当前 Secret 为本机明文配置（POSIX 0600），不是加密保险库；管理响应不回传 Secret。Hello 的浏览器草稿、完成标记、日志和截图不得包含 Secret。连接失败不回滚基础引导；更换连接身份按社交模块规则重新确认或配对。

原型采用只读假凭据与模拟结果；这不是正式实现的凭据输入方式，也不构成真实连接验证。

## 6. 配置落地与一致性

### 6.1 复用已核对入口

路由地址通过资源管理取得，不在 Hello 中复制路径常量。下表是现有能力，不是新增 Hello API 的承诺。

| 能力 | 已核对源码 | 接入注意 |
|---|---|---|
| 面板状态 | [Host](../app/dsh/host/index.js) | 现有状态对象与 generation 冲突检查；保留钱包、账本、日记等无关字段 |
| 感知状态/控制 | [感知 HTTP](../app/dsh/adapters/perception/http.js) | 状态查询；POST action 为 start/pause/stop；服务端执行后回读 |
| ABS 流速/时段 | [ABS HTTP](../app/dsh/adapters/abs/http.js) | time-scale 传 timeScale；rest-hours 传 enabled/start/end；不调用 mode |
| 钉钉配置/配对 | [社交 HTTP](../app/dsh/adapters/social/http.js) | 已有 configure/reload/pair_owner 等动作；具体负载遵循模块契约 |
| 完整人格读写 | 当前没有据此确认的完整覆盖接口 | 必须新增明确契约并验证动态变量装配，不能冒用 state.prompt |

### 6.2 拟议的 Hello 持久化状态

由核心定义版本化结构、存储适配落实。建议包含 `schemaVersion`、`flowVersion`、`status`、`currentStep`、`draft`、`appliedSteps`、`completedAt`，钉钉独立记录未开始/跳过/进行中/完成；这些字段是设计建议，不是现有 JSON 格式。

- 草稿不等于业务配置；“保存草稿”和“应用设置”状态分离。
- 同一提交重复点击不得重复启动采集、重复连接或重复发送测试消息。
- 跨模块不存在已确认的原子事务。先校验再逐项调用，保存成功项和失败原因；重试仅处理未确认步骤。
- 回读失败时显示“结果待确认”，先查询，避免重复副作用；无法确认时不设置完成标记。
- 不做伪回滚：停止采集或外发测试消息不能通过恢复 JSON 撤销。
- 使用统一资源路径、原子存储策略与迁移互斥边界；不在多个模块各建一份配置真相。

### 6.3 已有用户与升级

首次展示判断不能仅检查 hello 文件是否存在。结合现有资料与安装迁移信息，已有用户提供非阻塞入口，并从真实配置预填。升级引导版本只展示必要的新项，不重新初始化已有状态。重开引导不重置人格、感知、ABS、钉钉或个人资料。资料迁移期间禁止与配置写入交错；恢复后回读最新状态。

## 7. UI 约束与原型定位

- 参考 [共享模块样式](../app/dsh/ui/module-surface.css) 与 [原聊天页面](../app/dsh/ui/original.html)：墨色 `#243b5e`、辅助色 `#627d9e`、主色 `#316da9`、边框 `#e8f1fb`、浅底 `#f4f8ff`。
- 白色卡片约 20px 圆角，控件约 11px 圆角，轻阴影；使用现有字体栈，避免另起高饱和营销视觉。
- 桌面左侧流程、右侧角色与轻提示；窄屏以表单为主，角色不挤占必填操作区。角色使用共享素材，不引入新的宠物形象。
- 键盘可操作、焦点可见、表单有标签，错误不只靠颜色；尊重减少动画偏好，长 Prompt 展开不遮住返回/保存操作。
- 已制作的单文件 HTML 是交互设计参考：本地草稿、假凭据、静态示例，不包含真实配置提交。它不等于 Hello 模块实现或验收通过。
- 本文不依赖会过期的浏览器交接地址；原型若后续归档进仓库，应独立评审素材体积与维护方式。

## 8. 实施顺序与验收

建议按以下顺序落地，不在本次文档任务中实施：

1. 核定完整人格装配/覆盖方案，以及 ABS 运行模式与目标产品行为的差距。
2. 定义 hello 核心状态、存储和已有用户判断；补齐冲突、恢复、部分成功测试。
3. 接入人格、感知、ABS 基础流程，确保真实回读与副作用边界。
4. 接入可选钉钉向导，再验证实际连接、主人配对与双向消息。
5. 对齐 DSH UI、窄屏、键盘和减少动画表现，完成安装/升级回归。

### 验收清单（待实现后执行）

- [ ] 新用户能完成基础流程，不连接钉钉也能进入小鱼塘。
- [ ] 已有用户不会因缺少 hello 标记被重置，升级不覆盖自定义内容。
- [ ] 默认完整人格是真实维护的预设；编辑后只生效一次；动态能力说明仍正确装配；历史补充有明确兼容行为。
- [ ] 不存在性格底色卡和主动互动开关；流速操作不改变 ABS mode。
- [ ] 感知未选择不能误启动；不可用可跳过；启动失败不会显示运行中；选择关闭既有采集有明确提示。
- [ ] 流速快捷档位、自定义回填、暂停值、越界/非有限输入均有测试。
- [ ] 防打扰关闭、跨午夜、同日区间、边界时间、起止相同及 UTC+8 与浏览器时区不同均有测试。
- [ ] 草稿返回/恢复、重复提交、版本冲突、模块失败、回读不确定、迁移进行中均不造成覆盖或重复副作用。
- [ ] 钉钉保存/连接/配对/收发验证分开；错误与跳过不阻塞主流程；Secret 不落浏览器持久化及日志。
- [ ] 桌面与窄屏无横向溢出，长文本和错误提示可见，键盘焦点与标签可用。
- [ ] 回归现有 persona、perception、abs、social、migration 测试，并增加 hello 用例；集成实机结果与纯模拟测试分别记录。

## 9. 尚需实施时核定的细节

- 完整人格预设的唯一源码、版本管理、覆盖存储和恢复默认策略，如何与已安装 DSH 预设兼容。
