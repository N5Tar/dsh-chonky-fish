# 音色与情绪表达设计需求

设计阶段记录日期：2026-11-17。交付物为[设计方案](../voice-expression-design-v1.md)。以下需求表、方向和检查记录保留为设计阶段原文；实施结果见文末“2026-11-18 实施验收”。

## 已确认方向

独立语音模块支持多种云端、本地和自托管提供方，首期先接阿里云百炼。对话模型直接生成该厂商支持的情绪标签，不增加独立情绪推理。

**一条完整助手回复，一次合成，一个音频文件。整个方案不做分片，也不保留以后引入分片的路线；不增加清单、封口、部分语音附件或额外版本系统。** 保存失败不阻断本次可信内存音频播放。读取文件只需有截止时间的 Host 句柄保护，不引入外部读取租约/续租协议。

提供方标注流式音频输出能力，支持就自动边生成边播放，无需开关；不支持或未知时完整返回后播放。两种方式均一次提交完整文字，成功结束后才保存一个完整文件并显示回放按钮。

## 设计阶段检查记录（2026-11-17）

| 范围 | 结果与边界 |
| --- | --- |
| FR-1—FR-8、FR-11—FR-14、QR-1—QR-14 | 设计已定义；实现、真实账户和声音效果未验收 |
| FR-9—FR-10 | 沿用已完成的 HTML 原型交互验证；没有真实样音、付费接口或部分语音界面 |
| 来源与归档身份 | ASR/文字入口产出 `{text, source}` 元数据并随插件提交传递；prompt 适配边界通过既有 requestId 本地取用，登记失败/取消由适配器 abandon 并清理 prepared 记录，按 not_applied 收尾。回复归档使用现有 sessionId + seq，surface replacement/revoke 使旧关联失效 |
| review 修复 | 用简单单文件契约解决完整性；保留来源关联、历史格式、独立试听、存储降级和断连读取回收 |
| 流式能力确认 | 阿里云、MiniMax、豆包预设标记官方流式输出能力；按用户确认，支持即采用边生成边播放，一次请求、最终一个文件。实际首期仍只接阿里云 |
| 本轮 review 修复 | 明确播放器追加/结束输入/实际播完/停止，输出与麦克风等待本地播放结束；文件按实际格式保存，不再统一写成 .wav |

source 是插件提交元数据，不进入 LLM 正文，也不要求 DSH 字段；DSH 的通用 session.prompt 透传正文和 requestId。prompt 适配边界仅通过既有 requestId 的插件内存关联取回 source，不做重新识别或网络/数据库查询；claim/context 仍按现有消费事件关联实际输入。回复正文独立复用 sessionQuery.listEvents/readEvent 与 sessionId + seq 稳定引用。

HTML 沿用已验证的厂商能力标记与试听状态演示；设计阶段只更新设计和需求文档，没有修改 HTML 或运行代码。静态检查覆盖文档结构、相对链接、代码围栏、空白和旧接口残留；不能替代运行时测试。该阶段状态为 IN REVIEW。

### 退役路径与传输说明

- 已删除逐句/逐段输出与每句 120 字符上限；一次提交一条完整 assistant message，不因旧字符预算截断后重新合成。
- 已删除旧的整轮 `reply.final` 聚合、重合成式回放和将完整音频放入单次 JSON/base64 响应的旧路径。现在以 `reply.message` 的 `sessionId + seq` 关联消息，读取已归档文件做回放。
- HTTP SSE 的 `audio.data` 字段仍使用 base64 作为事件传输编码；它是分块 PCM 或单个完整 WAV 音频事件的传输表示，客户端解码成音频字节后交给共享播放器/文件归档，不是旧的一次性完整回复 JSON 回包。
- Windows 系统语音仍是现有默认提供方；完整 WAV 通过统一回复音频接口播放和归档，不保留逐句预算或单独的旧 TTS 播放路线。

### 验收方式及未覆盖项

本次本地命令结果：`npm run build`、`npm run test:voice`、`npm run test:tasks`、`npm test` 均通过；末尾空白复核 `git diff --check` 通过。`test:voice` 中的 Aliyun、Windows、sessionQuery、DSH HTTP/Host 与设置行为均为自动化 mock 或隔离 fixture；它们不提供真实凭证、真实音频设备或实际 DSH profile。

另行检查了已安装 DSH 0.2.1-rc.2 的隔离包：同步 `registerMessageProjection` 的进程内重放可行；该证据不验证正式 profile 的持久投影。唯一发现的写入接口 `appendPluginRecord` 是 experimental-only，本实现不调用它，不修改宿主，也不打开情绪注入 gate。阿里云账户凭证/网络响应、Windows 实机语音与麦克风/扬声器体验、用户实际 profile 的持久投影和冷恢复仍未验收。官方样音通过官方入口查看或试听，本仓未内嵌样音。
