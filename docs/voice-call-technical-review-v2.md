# 连续语音通话技术方案 v2 · 自审记录

- 日期：2026-11-14。
- 评审对象：[DSH 插件实施与桌面端扩展方案](voice-call-technical-v2.md)。
- 评审方法：设计者逐项检查仓库实现、已有架构约定与事件时序，发现问题直接修订；未使用独立评审者，未将文档推演当成功能测试。
- 结论：以下问题修订后完成复查，当前无已知未处理的架构或协议阻塞项。安装版本适配、音频运行、性能及回声仍需实施验收。

## 第一轮：复用边界与当前代码事实

| 发现的问题 | 修订 | 方案位置 |
| --- | --- | --- |
| v1 虽要求核心纯净，但端口仍直接出现 Session/source/rpcId，未来桌面可能复制 DSH 模型 | 定义通用 ConversationRef、提交身份、消费/回复事件；DSH 字段只存在适配器 | §1、§5、§7 |
| 浏览器采音放在 DSH UI 下，技术实现与页面生命周期耦合 | 可复用 Web 媒体放 shared/audio，DSH UI 只保留界面 | §3、§4 |
| 宿主与操作系统混用，Windows helper 可能被理解为 Windows APP 的一部分 | 明确 DSH/桌面与 OS 两维装配，Windows TTS 为共享平台能力 | §1、§4 |
| “以后换 ASR 就变桌面”遗漏独立会话运行时 | 桌面迁移先提供 Conversation 后端与核心承载，再替换设备/语音提供方 | §4、§11 |
| v1 客户端租约检查被称作 fencing，但 prompt 不原子检查租约 | 收紧保证：Host 可隔离 TTS，Session 仍可能接收在途 RPC；强 fencing 需后端原子支持 | §9 |
| v1 将 HTTP 描述为无私有 token，容易遗漏可用的宿主认证接入 | 对照现有 migration 路由，使用 connection.requestRejection；缺能力时拒绝写请求 | §2、§9 |
| 共享 resources 已有 CAS，不应为新功能另造一套配置并发机制 | voice 接入现有 updateConfig、sanitize/merge 和迁移屏障 | §2、§10 |

## 第二轮：启动、事件与数据生命周期

| 发现的问题 | 修订 | 方案位置 |
| --- | --- | --- |
| 等待异步能力检查后才 unlock，会失去浏览器用户手势上下文 | 应用装配层在点击同步栈 unlock，核心只接收就绪结果 | §6 |
| 按会话租约隔离仍允许两个窗口对不同会话同时录同一麦克风 | 首版每个本机 DSH Host 一个音频通话槽，核心只接收不透明 scope | §9 |
| 单块识别成功即释放音频，与随后整轮失败/超限重试冲突 | 整轮 accepted 或显式丢弃前保留可重建音频，并纳入 180 秒预算 | §6、§10 |
| 把本地尚未发出的块也算入单次 ASR 超时，会因排队误取消 | 本地积压与已发 RPC 执行期限分开；积压暂停新采音但不丢已有块 | §10 |
| inspect 后再 subscribe 存在事件遗漏窗口 | 同一订阅屏障建立基线与 live，connected 激活边界排除旧 turn | §5.1 |
| reply.final 若在 turn/end 前仍可被 surface 修改，名称与语义冲突 | DSH 适配在成功终态完成折叠，依序输出 final 与 ended | §5.1 |
| 新配置高版本若被旧 sanitizer 回退，会在保存其他设置时被破坏 | 不支持版本禁用 voice 编辑，非 voice 更新原样保留旧字段 | §10 |

第三轮资源核对另发现两处边界遗漏并修订：语音必须自行 retain 目标，不能借用 reset 会释放的 chatBridge 引用；跨 call 的未发送音频、unknown 记录与 drain 仍须计入同一实例预算。方案 §7、§10 增加独立引用、30 秒核对收尾与实例总量限制。

## 第三轮：替换适配器与故障时序复查

| 推演 | 复查结果 |
| --- | --- |
| 将 DSH adapter 换成不同 ID/cursor 的内存会话 | 核心只使用归一化事件与不透明身份；无需知道 rpcId 或事件 seq |
| 将 Web Capture 换成未来原生 Capture | 核心只接收采样序号、活动和音频 ref；原生对象不跨端口 |
| 将 Windows TTS 换成另一个合成后端 | 只需实现音频句柄、预算、取消与能力报告；页面与核心不读系统音色 API |
| UI 切页或未来桌面窗口隐藏 | service 所有权归插件 Client / 桌面后台，视图销毁不销毁通话 |
| 开启后能力失败或权限晚到 | 预热播放资源回滚，迟到轨道 stop，不进入 connected |
| A accepted → B 起音 → A 晚完成 | A 被 suppress；B 的 epoch 经自己的提交身份进入 turn，不被 A 冒用 |
| inbox accepted → RPC 报错 | accepted 不回退；不重发，不因本地 echo 删除否认宿主已收 |
| unknown → 用户显式重发 → 原请求后证实接收 | 新旧身份分开并有关联，提示可能重复；不误判为同一成功回执 |
| lease 过期 → 用户在新窗口接管 → 旧 renew/release 晚到 | 代号不匹配，旧请求不能续/释放新 owner；旧 prompt 仍按在途核对 |
| 扬声器停播 → 旧 onended → mute → gate 截止 | gate 不靠旧回调释放，截止只重算允许条件，不擅自开麦 |
| 前块识别成功、后块失败或全文超限 | 原音频整轮仍可重建，失败 held，不截断发送，不自动越序 |
| Host 重启或迁移通知延迟 | 客户端暂停；已发 prompt 结果仍可未知，不承诺撤回；重连不补播 |
| 反复挂断/重开，并在 reset 后保留旧 unknown | 原目标可短期核对；drain 到期释放引用，旧内容占原有预算，不能新 call 无限重置名额 |
| 将来加入流式识别 | v1 只承诺 final；interim 字幕等新语义需明确扩展，不能重用 final 冒充 |
