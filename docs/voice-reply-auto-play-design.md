# 大肥鱼回复自动播报（历史误解方案，已撤回）

2026-11-15 用户明确澄清：只有打电话状态才自动播报。本文件把这条要求错误扩大为“普通文字也开启输出”，该入口现已撤回。当前目标以[通话设计 v4](windows-voice-call-design-v4.md)和[技术方案 v3](voice-call-technical-v3.md)为准。以下保留此前实现及测试的历史，不是现行产品规则。

采用现有可移植语音核心的只播报模式，共享回复归属、文本处理、合成、音频释放、租约和取消逻辑；不另建一套播报队列。只播报模式无需识别服务，也不申请麦克风权限。

大肥鱼 composer 发送文字时，在用户动作调用栈中解锁输出，等待只播报订阅基线就绪后发送。播报准备失败仍正常发送文字并给出错误提示。只朗读新收到的本地对话回复，不重播历史，不朗读其他会话或外部来源。

点击麦克风按钮时转入原有连续语音输入与输出；再次点击结束收音和当前播报。下一次文字发送仍可自动启用只播报。只播报的内部会话连接不使麦克风按钮显示为开启。

重置、取消、插件卸载与模式切换都保留原有跨通话隔离：旧回复或迟到合成不能进入新模式；旧未知提交仍按既定身份核对，不补发。

验收覆盖：无 ASR/麦克风的文字回复播报；按钮关闭与只播报共存；语音与只播报切换；发送先订阅后入会话；失败不阻断文字；重置与迟到工作隔离；实际 DSH 中麦克风关闭时新回复的合成和播放。

自审补充：可选 ASR 扩展挂载或卸载会使能力缓存失效，但不能替换仍在工作的只播报核心、订阅或租约；`ensureSetup()` 复用现有服务，输入就绪状态由开麦流程独立刷新。回归验证了挂载后模型准备、卸载后继续输出均保留原只播报调用身份。
