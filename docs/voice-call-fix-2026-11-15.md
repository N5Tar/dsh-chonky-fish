# 语音通话启动与设备排查（2026-11-15）

## 现场与原因

用户报告 `A required voice capability is unavailable`。主 DSH 的按钮 tooltip 和 toast 确认了该错误；它来自核心开始录音之前的能力检查。重启后四项能力均通过，重启前未保存分项快照，因此不能据此确认原始报错的唯一来源。

代码排查与失败回归确认一个可重复的缺陷：控制器的 setup 和 `speechStatus` 具有应用生命周期，但本机 SenseVoice 在最近一次识别结束、闲置默认 300000 ms 后回收 worker，将准备状态从 ready 改为 standby。再次开启通话时，旧代码信任缓存的 ready、跳过准备；核心随后重新检查识别能力，返回上述通用错误。

另发现 DSH 在 Shadow DOM 内渲染对话页。构建会将初始模板的 SVG 符号展开，但按钮运行时重新写入的 `<use href="#i-mic">` 没有可解析的同根符号，导致按钮为空。

## 修订与自审

- 每次 Start 在已取得当前会话后重新读取 Speech catalog，再决定是否自动准备；异步返回后校验启动代次，取消或重置不能继续打开麦克风。
- 核心按采集、识别、播放、合成分别报告能力错误及 stage，明确标为未应用。composer 提供相应中文提示，保留单按钮界面。
- 按钮使用自身包含路径和 viewBox 的 SVG，避免依赖文档级符号。
- 回归先验证旧代码失败，再验证修复通过：ready → standby 的再次开启会重新 prepare；取消恢复过程不请求麦克风；四类能力错误在采集前返回；图标不依赖外部 use。
- 自审检查了新增 catalog await 的取消代次、重置顺序及页面重挂载；配置、会话目标、结束策略及旧输入不补发语义继续使用已有实现。
