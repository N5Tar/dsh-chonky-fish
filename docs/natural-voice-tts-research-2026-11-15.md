# 真人感语音生成方案与部署成本调研

调研日期：2026 年 11 月 15 日。适用场景：Chonky Fish 中文语音对话、固定角色音色、可中断播报。

当前最直接的升级是将 Windows System.Speech 换成支持自然韵律的神经网络 TTS。无需从零训练声音模型。建议先用云端 CosyVoice 建立听感基准，同时利用现有 RTX 4060 Ti 16GB 验证本地 CosyVoice 3；再比较 Qwen3-TTS、VoxCPM2 和 GPT-SoVITS。个人使用不必先租常驻 GPU，面向普通用户分发则更适合云 API 默认、本地服务可选。

以下价格是查询时的官方公开价格快照，不计免费额度和临时促销。听感优先级是针对项目的选型判断，尚未做同文本盲听或本机推理测速。

## 当前机械感与项目限制

`app/shared/platform/voice/windows-tts.ps1` 调用 `System.Speech.Synthesis.SpeechSynthesizer`，枚举系统已安装音色后输出 WAV；`windows-tts.js` 限制每次 120 字。目前没有神经网络音色生成、声音设计或声音克隆模型。

`app/dsh/client/voice/host.js` 将所有合成音频转成 16kHz 单声道，使用线性重采样。它会限制新模型高采样率音频的清晰度，但机械的语调仍需通过模型和韵律改善。

`core/modules/voice/service.js` 收到 `reply.final` 后，等待 `turn.ended` 才进入播报；随后逐句合成、逐句完整播放，再合成下一句。它既不能利用模型的首包流式输出，也没有下一句预合成，因此厂商宣称的百毫秒首包不会直接变成项目里的百毫秒响应。

现场硬件通过只读查询确认：RTX 4060 Ti，显存 16380 MiB；系统内存约 31.8 GiB。硬件具备本地候选模型验证条件，实际速度仍取决于模型、推理引擎、句长及其他应用占用。

## 音色怎样生成

“声纹”通常指用于区分说话人的声音特征。生成自然语音还需要模型生成发音、节奏、重音、停顿和情绪；只提取一个说话人向量不能独立完成这些工作。

可采用四种方式：

| 方式 | 输入 | 产物与适用场景 |
| --- | --- | --- |
| 预置神经网络音色 | 文字与音色 ID | 最快验证真人感，不要求准备录音 |
| 声音设计 | 年龄、音高、性格、说话方式等描述 | 生成原创角色声音，适合没有指定真人参考的宠物或助手 |
| 零样本声音克隆 | 一段单人参考录音，部分模型还需对应文本 | 保存参考提示或云端音色 ID，之后直接合成新文字，通常无需微调 |
| 专属音色微调 | 经整理标注的多段录音 | 优化长期一致性，增加数据整理、训练和模型维护成本 |

典型流程是“参考录音或声音描述 → 音色条件 → 输入回复文本 → 生成语音 → 播放”。音色条件可能包含说话人向量、参考音频编码和参考文本，不一定是可跨模型迁移的单一文件。

Qwen3-TTS 的 Base、CustomVoice、VoiceDesign 是不同用途的模型；Base 用于参考录音克隆，VoiceDesign 用描述生成声音。其 Base 支持约 3 秒参考样本，但项目试验建议准备 10～30 秒干净、无音乐、风格符合角色的授权录音，并人工核对参考文本。短样本可以工作，不代表越短越自然。[Qwen3-TTS 官方说明](https://github.com/QwenLM/Qwen3-TTS)

如果目标只是“像真人聊天”，应先试听预置音色和声音设计；只有希望“像某个具体的人”时，才需要克隆该人的声音。

云 API 无需专用 GPU，已有 Host 可承担代理与密钥管理。需要计入的额外成本包括网络、并发配额、失败重试和运维；请求中止不一定撤销已经发生的合成计费。角色音色先试听，再创建少量正式版本，避免为每轮对话重复创建音色。

## 本地与自托管模型

“支持流式”仅说明模型或配套引擎具有此能力，接入现有完整 WAV 协议后仍可能整句等待。下表没有标注官方下限的显存建议是用于试验的工程预算，不是实测或最低配置；均以单路推理为前提。

| 方案 | 能力与部署判断 | 硬件预算及当前机器适配 | 授权与成本注意 |
| --- | --- | --- | --- |
| CosyVoice 3，0.5B | 中文、方言、克隆和指令控制；官方提供双向流式与服务化路径，优先验证 | 建议用现有 16GB 卡单独部署试验 | 代码与所列权重 Apache 2.0；本地无字符调用费 |
| Qwen3-TTS，0.6B／1.7B | 预置音色、声音设计和克隆用途清楚；作为第二组听感对照 | 先验证 0.6B，再测 1.7B；为推理预留 8～16GB 显存预算 | 所列 Base 权重 Apache 2.0；服务端实现仍需验证实际流式输出 |
| VoxCPM2，2B | 声音设计、克隆、流式、48kHz 输出；值得比较自然节奏 | 官方列推理约 8GB 显存，现有 16GB 卡具备试验条件 | 代码和权重 Apache 2.0 |
| GPT-SoVITS，v2 ProPlus 等 | 克隆、少样本微调；官方有 Windows 整合包，固定角色值得试 | 现有 16GB 卡试验；不要直接套用作者 4060 Ti 的长文本吞吐数字估算首包 | 仓库 MIT；采用的权重与附属模型需分别检查 |
| IndexTTS 2.5 | 参考音频克隆、情绪、语速和发音控制 | 在现有 16GB 卡试验，先测短句首包与资源占用 | bilibili 自定义模型许可；需按该版本条款评估产品部署 |
| Fish S2-Pro／Drama 3 | 表现力与导演式控制候选，本地部署成本较高 | 官方分别要求至少 24GB／48GB 显存；当前卡不作为标准部署目标 | S2-Pro 权重为研究许可；Drama 3 为社区许可，不能按 Apache 方案估价 |
| F5-TTS | 参考音频克隆，可做技术对照 | 能否满足本机实时交互需测试 | 代码 MIT，官方预训练权重 CC-BY-NC，不作为默认商业候选 |
| Kokoro 82M | 轻量预置音色，适合作为无独显机器的候选降级方案 | 优先做 CPU 与中文音色测试 | 权重 Apache 2.0；标准用法不提供任意真人零样本克隆 |

对应官方资料：[CosyVoice 功能](https://github.com/QwenAudio/CosyVoice)与[权重](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512)、[Qwen3-TTS 权重](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base)、[VoxCPM2 配置](https://github.com/OpenBMB/VoxCPM#-models--versions)、[GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS)、[IndexTTS](https://github.com/index-tts/index-tts)、[Fish 硬件要求](https://speech.fish.audio/install/)与[许可](https://github.com/fishaudio/fish-speech)、[F5-TTS 许可](https://github.com/SWivid/F5-TTS#license)、[Kokoro 模型](https://huggingface.co/hexgrad/Kokoro-82M)与[音色](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)。

## 月度成本估算

统一假设：每天聊 30 分钟，助手发声占一半；助手以每分钟 220 个汉字说话，每月 30 天。输出约 99000 个汉字，以下按 10 万汉字预算。只算新增 TTS 合成，不含已有 ASR、LLM、音色创建、失败重试和其他基础设施费用。

| 方案 | 每月合成费近似值 |
| --- | --- |
| CosyVoice v3.5 Flash／Plus | 16／30 元 |
| Qwen Audio 3.1 TTS Plus | 28 元 |
| MiniMax 2.8 Turbo／HD | 40／70 元 |
| 豆包 2.0 按量 | 30 元 |
| Fish S2.1 Pro | 4.5 美元 |
| ElevenLabs v4 Turbo／v4 | 4／8 美元 |

上述数值从官方单价按纯汉字折算，真实混合文本应按请求内容统计。语速和双方发声比例是预算假设，30 分钟通话不等于 30 分钟 TTS 输出。

### 利用现有显卡

不新增显卡购买和 GPU 租金，但仍有功耗、模型下载存储及维护成本。作为算例，若 TTS 带来的整机增量功耗为 60～150W、电价按 0.6 元／kWh，每月实际运行 30 小时，对应约 1.08～2.70 元增量电费；这两个功耗端点是预算假设，需要用本机测量替换。若增量功耗全天存在，每月 720 小时则约 25.92～64.80 元。不能把“本地免费”理解为整机常驻没有成本。

本地体验的主要成本可能是等待和资源竞争。TTS、ASR、本地 LLM、桌面渲染共享显存时，应先串行测量，再决定模型常驻与空闲卸载策略；不要直接把多个模型峰值预算相加后假定能够流畅并行。

### 租 GPU 服务器

AutoDL 官方公开页的 RTX 4090 24GB 标价为 1.88 元／小时、RTX 3090 24GB 为 1.32 元／小时，库存、区域和优惠以实际报价为准。按 30 天全天开机，纯计算费用分别约 1353.60 元和 950.40 元，另计存储、网络和服务运维。按需开机可以降低计算支出，但冷启动与模型加载不适合随时来一句的桌面对话。[AutoDL 公开报价](https://autodl.com/)

用 1353.60 元对比 CosyVoice Flash／Plus 的字符费，算术交点约为每月 846 万／451 万汉字。这只是“GPU 租金与 API 字符账单相等”的预算比较，不是推荐迁移阈值：模型效果、并发吞吐、空闲率、存储和人力均未折算，音色和性能也不保证等价。

本地模型封装还需要独立 Python 环境、固定版本、健康检查、预热、进程回收及故障诊断。给用户分发时还需处理模型下载、驱动和平台兼容，这些工作往往比个人使用时节省的几十元 API 费更贵。

## 接入建议

保留目前 ASR、对话模型和打断控制，新增可替换的合成提供方。在个人机器上采用“Host → 本地 Python TTS 服务”；在线方案采用“Host → 厂商 API”，密钥由 Host 管理。统一提供音色枚举、合成、取消和能力信息，配置分别保存 provider、model、voiceId／参考素材标识；不要继续把 `windows-system-speech` 写死在客户端。

第一阶段先用完整 WAV 替换合成源，最小化链路变化，确认音色改善。之后让播放存储接受输出采样率，ASR 输入继续保留其 16kHz 约束；48kHz、30 秒、16 位单声道约 2.88MB，已超过现有单片 2MiB 限制，放宽采样率时必须同时调整有界缓冲预算。

第二阶段增加下一句有限预合成，减少句间等待；进一步改为流式 PCM 输出和播放，再考虑从对话文本增量中提取可朗读句子。文本增量播报需保留当前代次校验和打断丢弃语义，防止把工具中间文本或过期回复读出来。

语音文本也应单独生成适合听的短句：控制每轮长度、用自然口语、保留合理标点和停顿。先统一角色声音，再小幅调整情绪；更高采样率和音色相似度本身不会自动带来对话感。

原生实时语音到语音模型是另一条路线，例如 Qwen Audio Realtime、豆包实时语音模型。它需要重新评估会话状态、工具调用和音频 Token 账单。当前已有文字对话与工具链，优先更换 TTS 能更快隔离和解决声音问题。

## 建议验证顺序

1. 用 CosyVoice v3.5 Flash／Plus 与 MiniMax 2.8 HD 的预置音色试听，建立自然度基准；豆包 2.0 作为中文对照。
2. 本机依次运行 CosyVoice 3、Qwen3-TTS 和 VoxCPM2，Windows 部署便利性另比较 GPT-SoVITS。每次仅加载一个候选。
3. 若要原创角色音色，先做声音设计；若要指定真人音色，再使用同一段授权参考录音做克隆比较。零样本一致性不足时才考虑微调。
4. 用同一组约 30 条句子盲听，覆盖短回复、疑问、安慰、数字日期、多音字、中英混读和长句。记录自然度、角色一致性、错读漏读、音色漂移、冷／热启动首包 p50／p95、实时率 RTF、峰值显存、句间间隙、打断后残留和真实账单。RTF 小于 1 表示生成速度快于播放速度，不代表首包很快。

个人使用优先比较现有显卡本地运行与按量 API。若要让没有独显的用户安装即用，采用云 API 默认、本地可选更稳妥。确定同文本试听结果后，再选择是否投入本地服务与流式播放的工程工作。
