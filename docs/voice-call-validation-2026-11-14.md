# Windows DSH 连续语音验收记录 · 2026-11-14

状态：单按钮功能实施与本次验收完成；未覆盖的设备与系统场景在下文明确列出。此记录区分单元测试、真实组件测试与完整通话，不以替身端口测试代替 DSH 验收。

## 环境与隔离

- Windows x64；实际安装的 DSH `0.2.2-rc.1`，Electron `44.7`，内置 Node `24.21`。
- 用户主 DSH 因插件加载错误进入停用第三方插件的恢复模式。后续验证使用独立配置、数据和会话目录，不修改主程序的恢复配置。
- 隔离宿主使用实际安装包的 `dsh-desktop-host` 和 Web Client，加载本仓库插件及 DSH 实验语音包；ASR 复用本机已准备好的模型副本。
- 输入为本机 System.Speech 生成的二十个中文测试 WAV，16 kHz / 单声道 / PCM16；通过测试浏览器的 MediaStream 输入，生产代码没有增加测试绕过入口。
- 最终界面按用户后续要求改为[单按钮 v3](windows-voice-call-design-v3.md)，只在 composer 发送按钮旁呈现语音入口。此前通话条的验收数据作为核心链路历史证据，单按钮重新独立验证。

## 审查与实际测试发现的问题

| 问题 | 处理与验证状态 |
| --- | --- |
| 直接访问可选 `remote.speech` 导致 Cordis 加载错误 | 改为注入作用域访问；生成 Client 的缺失 / 存在能力回归及隔离真实挂载通过 |
| Worker 私有 `let ort` 与 ORT UMD 全局变量冲突 | 改名，补实际固定 UMD 的 classic Worker 加载回归；真实浏览器通话已进入 connected |
| 基线中已运行的自主回复可能被播报 | 适配器排除基线终态，核心要求已追踪的新 turn；回归通过 |
| 键盘接收未推进播报代次，结果不明时提前清理身份 | 补接收 / 消费事件、证明规则与有界关联保留；回归通过 |
| 资源验证后文件改变仍沿用旧摘要键 | 按不可变键缓存已验证字节；文件替换回归通过 |
| 会话重置的收音清理与旧请求核对 | 同一服务保留输入与短期 drain；媒体与租约清理后再切换，延迟证据、旧回复、迟到合成和尾音回归通过 |
| 扬声器播报超过两秒触发错误停采 | 修复意图暂停与真实采样中断的区分；后续二十轮实际通话复测通过 |
| 插话后停止状态未及时发布、异步 stop 可能覆盖新播放 | stop 按令牌与 run 串行化，完成后发布 idle，新回复等待停止完成后重新校验；服务 27 组回归通过 |

## 最终收尾验证

- 单按钮长期运行与逐轮无手动停止 / 发送已完成。结束时的失败待发清理、未知结果身份及重叠通话引用补丁已完成独立复查；核心服务 33 组、复制引用的 scopeId 测试、真实核心 / DSH 适配集成、乱序释放和冷启动取消测试通过，最终构建另完成上述三轮及结束 / 重开闭环。
- 最小化测试因检测到用户正在操作主 DSH 而未执行；没有据窗口可见状态声称已通过最小化。硬件拔插、休眠和所有蓝牙设备也不在本次已取得的实际证据内。
- 最终生成文件和打包清单已核对：247 个文件，21,922,688 字节；Worker、Worklet、模型、WASM、清单和 Windows 辅助脚本齐全，不含旧通话条 / 设置模块。主 DSH 已加载单按钮界面且无插件加载错误；原会话指向及真实麦克风方法已恢复，未自动重开用户手动结束的通话。
- 测试宿主与浏览器已关闭；临时凭据副本及两套 ASR 模型副本已删除，仅保留自行生成的测试语音、日志、截图与验收数据。
