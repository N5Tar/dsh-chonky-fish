## 1. 目标与确定的产品行为

用户点击一次「和鱼鱼语音通话」，就可以像打电话一样持续交流：说完后自动识别、自动发送，鱼鱼的回复自动播放；一轮结束自动回到聆听，无需逐轮点击录音、停止或发送。文字记录继续保存在当前真实 DSH 会话里。

首版必须同时交付输入与输出。默认使用本机识别和 Windows 本地语音合成；回复音色以系统实际可用音色为准，专属角色音色后续再做。开启通话前检查麦克风、识别器、中文音色和播放能力，缺任一项都给出具体修复入口。

| 决策 | 首版行为 |
| --- | --- |
| 结束一句 | 根据人声与静音自动判断；默认约 1.2 秒静音确认一句结束，可调节 |
| 自动发送 | 识别成功即按顺序提交，不要求每句确认；空白、纯静音不提交 |
| 发送目标 | 开启时绑定的大肥鱼真实 DSH 会话，禁止中途追随新的当前会话 |
| 语音输出 | 播放通话开启后该会话新完成的鱼鱼回复正文，保留同步文字 |
| 边听边说 | 耳机模式支持；说话可打断当前朗读，并保留用户起音 |
| 扬声器 | 经过回声验证才启用边听边说；未通过时自动轮流说话，明确显示模式 |
| 正在生成时说话 | 继续收音，自动排队；不隐式取消 Agent 正在执行的任务 |
| 结束通话 | 立即停止收音和播放，不再自动提交尾句或队列；未发送内容保留供处理 |
| 通话恢复 | 挂断、刷新、重启、锁屏后均不自动打开麦克风 |

“持续沟通”指通话连接与自动轮次持续存在。扬声器降级模式在播报期间暂停接收语音，播放完自动恢复；页面必须写明「鱼鱼说完后我再听」，不能宣称这一模式能随时说话打断。

## 2. 聊天页与通话条

在现有输入框发送按钮旁增加麦克风按钮，标签「和鱼鱼语音通话」，不改变键盘输入方式。首次点击展开就绪检查；模型下载由用户点击「准备识别模型」启动，不在页面打开时下载或收音。全部就绪后，由「开始通话」这个用户手势打开音频播放并申请麦克风；以后点击入口可直接开始。

通话开始后，在输入框上方固定显示通话条，鱼鱼舞台保持可见。布局示意：

```text
┌ 和大肥鱼聊天 ───────────────────────────────┐
│ 用户：明天下午三点提醒我开会。                │
│ 鱼鱼：好呀，我来帮你安排。           [重播]    │
│                                            │
│ ● 通话中  02:14  ·  正在聆听…                │
│ ▁▂▅▃▁  识别结果 / 待发送状态                 │
│ [麦克风静音] [回复声音：开] [设置] [结束通话]  │
│ 输入文字也可以…                      [发送]  │
└────────────────────────────────────────────┘
```

音量波形来自实际采样，不能用动画假装收到声音。初版只有收音指示与最终识别文本，不承诺实时逐字字幕。最终文本短暂显示「正在发送」后进入聊天记录；失败则停在独立待处理区，不覆盖输入框。

| 通话条状态 | 文案与操作 |
| --- | --- |
| 准备中 | 「正在连接识别器 / 请求麦克风权限」，可取消 |
| 聆听 | 「正在聆听，说完会自动发送」；显示真实音量 |
| 用户正在说话 | 「我在听…」；麦克风持续开启 |
| 识别中 | 「正在识别上一句，仍可继续说」；轮流模式按实际状态显示 |
| 等待 DSH | 「鱼鱼正在处理，已排队 1 句」 |
| 播放中 | 「鱼鱼正在说…」；耳机模式附「说话可打断」 |
| 麦克风静音 | 「麦克风已静音」；鱼鱼仍可回复和播放 |
| 积压暂停 | 「待处理语音较多，已暂停收音」；显示队列，可继续或结束 |
| 故障暂停 | 「麦克风断开 / 识别器不可用 / 回复无法播放」；明确重试对象 |

通话条中收音、识别、DSH 处理与播放可同时发生，采用一个主要状态加辅助状态，例如「正在聆听 · 上一句识别中」，避免把“识别中”误展示成麦克风已关闭。

## 3. 正常对话与自动断句

1. 用户开启，确认进入「正在聆听」。用户说「帮我记一下」，停顿 0.5 秒，再说「明天下午三点开会」。
2. 短停顿不提交；连续静音达到阈值后，将同一轮完整内容交给识别器。识别器的内部切段不等于聊天轮次。
3. 收到最终文本后，独立投递到 DSH，聊天中出现一条真实用户消息。键盘草稿保持原样。
4. 鱼鱼完成回复后，自动读出可朗读正文。说话期间以实际播放状态驱动舞台提示，不把模型生成当成已经发声。
5. 用户直接说下一句；耳机模式可在识别、生成或播放期间接着说。轮流模式在播报后自动恢复聆听。

断句设置提供「更快发送（0.8 秒）/ 标准（1.2 秒）/ 等我多想一下（1.8 秒）」。这些是待校准的初始值，不是语言理解承诺。超过阈值才想起补充时，将补充作为下一条消息；不撤回已提交文本，也不偷偷合并历史消息。

长时间连续说话按识别接口限制切成音频块，仍属于同一轮并按顺序合并文本。到达 90 秒连续发言上限时自动结束该轮并开始下一轮，通话条提前提示「将分成下一条发送」，避免无限录音和内存增长。

## 4. 打断、生成与回声

耳机模式中，检测到有效用户人声后，立即停止当前回复播放并取消其剩余朗读。鱼鱼刚说的内容留在文字记录；当前回复不会在用户停顿后突然续播。被打断的消息可点「重播」。

打断朗读不等于取消 DSH 任务。若 Agent 尚在执行，用户的新一句识别后排队，条上显示「已听到，等鱼鱼处理完」。如确实要停止任务，使用现有宿主停止能力；没有经过核对的取消接口就不新增虚假的“已停止任务”按钮。

有用户声音、未处理用户轮次或键盘提交时，不启动旧回复的朗读。新输入使之前回复的待播内容过期；后到的旧回复仍显示文字，但不插到新对话中播放。用户一句仅有噪声或无法识别时，也不擅自恢复刚被打断的声音。

扬声器模式不能只凭浏览器声明支持回声消除就认为可靠。设置页提供短句播放与真人插话测试；测试失败使用自动轮流模式：播报期间暂停收音判定并清除回声尾音，随后自动聆听。麦克风与输出设备发生变化后，撤销之前的扬声器全双工验证。

## 5. 朗读范围

- 只读当前通话期间新完成的助手可见文字，首版等本轮成功结束后按句播放；不追读历史记录，不逐 token 朗读。
- 过滤思考内容、工具请求及返回、隐藏旁白。Markdown 标题和列表转为自然停顿，链接读显示文字，不逐字读 URL；代码块或过长表格提示「详细内容放在文字里」。不另调模型改写答案。
- 默认每条自动朗读最多 800 个字符，末尾说明「其余内容可以看文字，或点击全文朗读」。全文朗读仍可打断，不一次性预合成整篇。
- 通话期间，当前会话中新产生的主动回复也可播报；钉钉等外部输入触发的 turn 默认不自动朗读。来源混合或不明时保留文字，不猜归属。
- 重连后不补播断线期间或已经播放过的回复。开启通话时正在进行的旧 turn 不自动朗读。
- 「回复声音：关」只关闭输出，不结束自动识别与发送；重新打开后只播报新的回复，不清空积压再补读。

## 6. 挂断、静音与离开

点击「结束通话」后，立即停止麦克风轨道与所有播放，停止自动投递。已经被 DSH 接收的消息继续由 DSH 处理，挂断不会撤回任务。当前录到一半的尾句、尚未提交的识别结果留在「未发送语音」区，提供编辑后发送、重试识别与丢弃；发送按钮必须明确显示文本和原目标会话。

静音立即释放麦克风，暂停当前未完成轮次，不自动发送尾句；未提交内容进入同一待处理区。取消静音重新申请收音并建立新轮次。关闭回复声音则立即停止播放，麦克风行为不变。

切换到插件内其他页面时，由插件级控制器维持通话，页面顶部仍显示通话条和结束按钮；页面切换不能导致两套录音。若新对话/reset 改变目标 Session，则先结束旧通话，旧结果只能留在旧会话的未发送区。

Windows 切换其他应用、窗口失焦本身不挂断。应用最小化后，在音频持续可用时继续通话；若运行时暂停音频、系统休眠或锁屏导致采集不可证实，立即进入暂停状态，恢复后显示「通话已暂停，点击继续」，不自动重新收音。DSH 退出、插件禁用或崩溃后，内存里的未发送语音无法保证恢复，页面关闭前应明确提示存在未发送内容。

## 7. 异常反馈

| 情况 | 行为 |
| --- | --- |
| 未启用宿主识别能力 / 缺模型 | 显示插件设置或准备入口；不反复弹麦克风权限 |
| 采样为零 / 设备无信号 | 提示检查输入设备，显示电平；持续静音本身不当成设备故障 |
| 识别失败 / 超时 | 保留对应音频供本次页面内手动重试；后续轮次暂存，不能越过失败轮次自动投递 |
| DSH 明确拒绝接收 | 保留可编辑文本；可以重试或跳过 |
| DSH 回执未知 | 暂停投递，提示核对会话；不自动重发，不退回演示回复 |
| 回复音色缺失 | 提供中文语音安装说明与重新检查；不伪装成通话完整可用 |
| 播放失败 | 文字回复保留，提示「声音未播放」；进入声音故障状态，用户可选择继续仅语音输入或修复 |
| 处理积压 | 在明确上限前暂停收音，已接收内容不静默丢弃；用户显式继续 |

## 8. 验收与发布范围

Windows x64 DSH 桌面版是首个支持目标；安装版本、原生识别运行时与中文音色必须记录。首版不宣称 Windows ARM64、其他操作系统或远程浏览器已支持。

必须通过：连续 20 轮无需点击发送；噪声与纯静音不产生消息；短暂停顿合并；耳机播报插话不丢句首；扬声器无自问自答；输入框草稿保留；挂断立即停止收音与播放；旧会话回调不串会话；失败和断线不重发；长对话内存有界。完整矩阵与性能目标见技术方案。

独立输入、只有朗读、只有手动录音停止都不构成本需求完成。自动轮流模式属于明确标识的兼容模式，不能替代耳机下持续双向交流的主路径验收。
