# 大肥鱼 · 单按钮连续语音设计 v3

日期：2026-11-14。按用户最新要求收缩 DSH 界面；本版替代 v2 的悬浮通话条、展开状态区、设置、重播与待处理操作面板。连续语音输入、自动发送和回复播报目标不变。

2026-11-15：本版限制由[通话设计 v4](windows-voice-call-design-v4.md)更新。此前短暂加入的“非通话自动播报”源自误解，已撤回；只有显式开启电话式通话才播报。v4 要求通用长任务期间持续对话及扬声器插话，主体改造尚待实施。

## 唯一入口

只在大肥鱼对话界面的 composer 中、发送按钮旁边放置一个语音按钮。聊天页面外不显示悬浮入口或语音面板。

| 状态 | 唯一按钮 | 点击结果 |
| --- | --- | --- |
| 未开启 / 已结束 / 启动失败 | 麦克风图标；title 与可访问名称「开始语音通话」；aria-pressed=false | 开始能力检查与通话 |
| 正在启动或准备识别模型 | 切换为结束图标；可访问名称「取消语音启动」；aria-pressed=true | 取消本次启动与模型准备，迟到结果不能打开麦克风 |
| 已接通 | 保持结束图标与按下态 | 停止采音、识别和播报，结束通话，不撤回 DSH 已接收的任务 |
| 正在结束 | 保持结束图标 | 合并重复结束操作，清理完成后回到未开启状态 |

开启和关闭都不需要第二个按钮。错误复用聊天页面已有的轻提示与按钮 title，不增加语音专用展开区。按钮支持键盘、明确可访问名称与按下态，图标本身不作为唯一状态信息。

## 一次点击后的行为

1. 在点击同步栈中解锁播放能力，检查本机 Windows、DSH Speech、会话目标和系统合成能力。
2. DSH 识别模型未准备好时自动准备；仍使用同一个按钮取消。没有 Speech 扩展或模型不可用时提示具体问题，不自动修改宿主插件配置。
3. 接通后持续收音，默认约 1.2 秒静音断句，识别后自动向当前规范鱼塘会话发送。
4. 助手成功结束的新增回复自动播报。默认扬声器轮流说话：播报结束后自动恢复收音。
5. 再次点击结束。未确认的在途请求仍遵循核对与不自动重发规则；关闭按钮不表示撤回模型任务。

单按钮版没有失败输入管理面板，因此显式结束通话同时结束本地待发意图：确认未提交的内容释放；结果不明或在途请求仅保留有界身份与正文用于最长 30 秒后台核对，不补发到下一次通话，也不继续占用新通话的活动输入名额。迟到接收证明仍可把结果确认成已接收。此策略由 DSH 装配层显式启用，核心默认保留策略继续供未来带恢复界面的桌面端使用。

DSH 会话本身必须已经配置可用的对话模型。模型调用失败时保留「已接收」事实，提示在该鱼塘会话修复模型或凭据，不把同一输入当作未发送内容重发。

## 页面与应用生命周期

语音控制器归插件 Client 的应用生命周期。composer 挂载时订阅，页面离开时仅解除视图订阅；切页不结束正在进行的通话。返回对话页面时从同一控制器读取按钮状态，包括模型准备期间的启动状态。

重置会话先结束旧通话再切换目标；插件卸载和应用退出释放音轨、Worker、Context、租约和订阅。启动取消、挂断、重置和旧回复迟到都不能重新开麦、续播或串入新通话。

## 复用边界与验收

界面收缩不改变 `core/modules/voice` 的轮次、投递证据、未知结果、预算与取消契约。未来桌面端可装配独立 UI，使用同一核心与共享音频 / 平台实现；DSH 的单按钮留在 `app/dsh/ui`，不成为核心依赖。

本版须实测：composer 只有一个语音按钮；没有旧悬浮通话条；开启、取消启动、结束均可点击；持续两轮以上不需要手动停止或发送；回复播放后继续聆听；页面往返和插件卸载不遗留订阅。完整代码复查及运行记录分别见 [实施 review](voice-call-implementation-review.md) 和 [验收记录](voice-call-validation-2026-11-14.md)。
