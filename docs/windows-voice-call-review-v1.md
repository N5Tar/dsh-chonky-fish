# Windows 连续语音通话 · 自审与修订记录 v1

- 日期：2026-11-14。
- 范围：[产品设计 v2](windows-voice-call-design-v2.md)、[技术方案 v1](windows-voice-call-technical-v1.md)。
- 方法：由本轮设计者逐段核对仓库与上游源码，再按事件顺序推演正常、失败、取消及竞态路径；没有将自审冒充独立评审或运行测试。
- 结论：三轮审阅及修订后，当前未发现尚未处理的设计阻塞项。Windows 真机集成、性能与回声验证仍属于实施验收，不能承诺方案绝无问题。

## 第一轮：需求与接入事实

| 发现 | 修订后的约束 | 位置 |
| --- | --- | --- |
| 早期设想把回复朗读排除在首轮验收之外 | 输入与输出同时构成首版；旧稿增加当前文档入口 | 产品 §1、§8，旧稿开头 |
| 直接调用表单会遇到 busy 丢输入、清草稿与错误演示降级 | 独立有序投递，保留键盘草稿，错误不走 sendDemo | 技术 §1、§5 |
| 只有内部 turnId 不能关联真实提交 | 核对上游 beginSubmission / requestId / source.rpcId；明确最低能力门槛 | 技术 §1、§5 |
| Remote 未必由稳定 API 默认挂载 | 显式核对 contribution 所有权与释放；缺能力不能伪装就绪 | 技术 §1 |
| 音频按秒限制可能仍超字节预算或格式不符 | 同时限制 WAV 头、16 kHz 单声道 PCM16、样本数、字节与 base64 复制 | 技术 §4、§9 |
| 将 AEC 支持标志当作扬声器防回声保证 | 耳机主路径；扬声器默认自动轮流，完整测试后才开全双工 | 产品 §4，技术 §8 |

## 第二轮：来源、顺序与资源

| 发现 | 修订后的约束 | 位置 |
| --- | --- | --- |
| 钉钉桥接也会产生 source.kind=user | 复用现有 isChannelUserMessage，检查 social 消息身份；混合来源不自动读 | 技术 §6 |
| A、B 连说后，A 晚到的回复可能被赋予 B 的最新 epoch | epoch 随输入身份传播到实际消费它的 DSH turn，不在回复到达时赋值 | 技术 §3、§6 |
| inbox 接收比 RPC 回执更早，后到错误可能覆盖成功 | 已证明 accepted 单向保持；查 rpcId、inbox 与日志，不凭文本猜重 | 技术 §5 |
| 同步合成阻塞控制循环，导致 cancel 不生效 | 异步合成、独立读取、取消 settled 截止与助手回收；客户端先立即停播 | 技术 §7 |
| 只限制 WAV 大小，遗漏解码后 AudioBuffer 与多份复制 | 增加解码预算和总工作集预留，识别及播放队列分别有界 | 技术 §7、§9 |
| 插件级实例仅保证同窗口，不保证第二个 DSH 窗口 | 复用 overlay 保持结束入口；Host Session 租约拒绝重复通话 | 技术 §2 |
| 失败轮次后仍投递后续结果会打乱用户原意 | failed / unknown / held 阻塞后续，显式跳过或处理 | 产品 §7，技术 §5 |

## 第三轮：关闭与并发状态一致性

| 发现 | 修订后的约束 | 位置 |
| --- | --- | --- |
| 测试矩阵把关闭回复声音也写成禁止自动发送，与目标冲突 | 拆开 mute、声音关闭、挂断；只有关闭声音时输入继续 | 技术 §10 |
| 停播后 generation 改变，忽略旧 onended 可能使扬声器输入永久门控 | 主动 stop 独立管理尾音期限与 gateGeneration | 技术 §7 |
| 门控结束回调可能在挂断或静音后重新开麦 | 结束时重新计算当前允许条件，禁止回调直接启动采音 | 技术 §7 |
| 取消准备时麦克风权限可能稍后成功 | late getUserMedia 轨道立即 stop，启动失败回滚 | 技术 §3 |
| result.ok=false 或本地 echo 失败不代表宿主没有接收 | 仅已核对的接收前拒绝码可安全重试；其余 unknown | 技术 §5 |
| 首轮长文本、持续积压或去重表可能无限增长 | 按输入预留、硬限长、失败块保留、有界最近集合与高水位 | 技术 §9 |

修订后再次按以下事件轨迹核对设计，没有发现新的矛盾：

| 事件轨迹 | 预期终态 |
| --- | --- |
| 开启 → A 起音 → 短停顿 → A 尾句 → 长静音 → 接收 → turn 成功 → 播放 | 一条真实用户消息，一次自动回复播报，随后仍聆听 |
| A 接收 → B 起音 → A 回复晚到 → B 接收并完成 | A 仅文字，B 可播报；A 不抢占 B 的交流 |
| 播报 → 用户插话 → 转写失败 → 用户丢弃本句 | 旧播报不复活，用户可重新说或显式重播 |
| submit → inbox 出现相同 rpcId → RPC 传输错误 | accepted 不回退、不重发 |
| submit → 断线 → 日志可见窗口暂无该项 | unknown，禁止因“暂时看不见”自动重发 |
| 扬声器播报 → 关闭回复声音 → 旧 onended → 尾音到期 | 旧回调不启动新句，尾音到期恢复输入 |
| 同上 → 尾音到期前 mute 或挂断 | 到期回调不能重开麦克风 |
| preparing → 用户取消 → getUserMedia 才成功 | 所有迟到轨道释放，call 保持 off |
| 识别中 → reset Session → 旧识别成功 | 保留旧目标下的未发送内容，不自动写入新 Session |
| 采音中 → 租约续期失败 → 第二窗口开启 | 旧窗口暂停新提交与采音，不自动抢回通话 |
| 8 轮未解决 / 样本预算到限 → 仍有在途结果 | 保留预留空间，暂停新输入，不丢队列中已接收内容 |

## 实际检查与证据边界

- 阅读现有 runtime、createFishChat、事件采集、social 来源判定和资源规格，未修改功能代码。
- 核对上游固定 commit 的 Speech Remote、挂载方式、WAV 校验和 Session requestId 契约；修正早期文档指向不存在 main 分支的语音链接。
- 本机 Windows PowerShell 5.1 成功加载 System.Speech；检测到可用中文音色，并在内存合成中文短句为 131622 字节 RIFF WAV，单次约 69 ms。未播放、未开麦、未保存音频。
- 文档执行空白差异检查与相对链接存在性检查；不运行无关业务测试，不把设计矩阵标成已经通过的功能测试。

实施前还必须完成技术方案 §10 的 A 阶段：安装版本兼容、真实 Remote 调用、Worker/WASM/CSP、麦克风持续采集、实际播放及取消。实施后再验收回声、插话、后台生命周期、20 轮闭环与性能指标。这些是明确的验证门槛，当前没有虚构通过结果。
